# TaskFoundry 项目说明

## 项目定位

TaskFoundry 是一套面向科研任务的出题与验证流程。它把研究材料转化为可独立完成、可重复评分的科学问题，再通过真实的盲解检验题目是否清晰、可解、具有足够难度，并把每次验证留下可追溯记录。

这套流程的重点不是批量生成题面，而是建立一个稳定的质量闭环：题目要有科学依据，解题所需的信息要完整，答案要能被独立核验，同时不能靠标签、文件名或简单规则猜中答案。

## 一道题如何完成

### 1. 题纲生成

首先根据输入材料形成 Question Design Brief，明确研究目标、候选方法、需要比较的科学指标、预期难点、数据边界、评分方式和验证条件。题纲保存在对应题号目录中，并同时保留“当前版本”和“已确认版本”两份，便于汇报与追踪，但不堆积无效历史版本。

输入不一定是几道现成题目，也可以是一个研究课题、一篇或多篇论文、一个知识图谱、一个软件工具链或一组数据。系统先识别输入的结构，再选择合适的题型模板：例如方法选择、方法比较、工作流设计或结果复核。输入类型会影响来源整理和题面表达，但不会改变质量底线。

### 2. 加载题型规范

题纲确定后，系统按“角色 + 题型 + 阶段 + 输入 profile”加载对应的 Skill Bank 版本。出题阶段使用 outline skill，正式编题阶段使用 author skill；两者都基于同一套项目级规范，但职责不同：前者约束设计，后者约束题面、资源、参考答案和 verifier 的落地。

每一批任务开始时固定 Execution Skill、Bank Snapshot 和 Experience Cards。批次运行期间不临时改规则，确保不同题目的结果可以比较。通用流程和质量底线放在 Execution Skill 中；只适用于某个领域、来源或题型的经验放在 Experience Card 中。

### 3. 出题与解题迭代

依据冻结题纲生成正式题包，包括公开说明、公开资源、参考答案、评分器和必要的验证数据。随后使用与正式评测一致的 Researcher profile 进行全新盲解。

盲解不是形式上的试运行，而是对题目的真实检验：

- 解题者能否仅凭公开说明和资源完成任务；
- 参考答案与 verifier 是否一致；
- 题目是否需要真正比较科学方法，而不是查表或猜标签；
- 结果是否稳定、可重复，并能在合理时间内完成；
- 提示之后，解题过程是否朝正确方向发展。

如果第一轮就得到满分，流程不会机械地继续重复同一题，而是根据 trace 判断题目是否过易；必要时提高隐藏工况难度、减少可直接利用的线索，再开启新的验证会话。提示解用于判断可解性和瓶颈位置，不以单一分数变化替代对解题过程的分析。

### 4. 归因、迭代与收敛

每次失败先归因：平台或环境故障、资源缺失、verifier 错误、题面歧义、科学设计问题和 Skill 不合规分别记录。只有确实属于出题知识或流程的问题，才进入 Skill Bank 演化。

同类失败至少形成稳定模式后，才生成 Candidate Lesson。候选规则必须通过三类检验：能修复原失败、能迁移到未见过的同类任务、不会破坏冻结回归集中的正确性、可解性、难度和防捷径能力。通过后才进入新的 stable 版本；未通过的经验只保留在 Evolution Memory 中，不影响运行中的规则。

## 哪些部分可以共用

不同领域都可以共用以下能力：

- 题纲、题包、trace、资源清单和版本封签的组织方式；
- public / private 数据边界和最小公开信息原则；
- 盲解、提示、评分、失败归因和发布门禁；
- 重复提交、异常文件、非有限数值、符号链接和额外输出的安全处理；
- Harbor 执行、结果收集、回放和证据链；
- Skill Bank 的 resolve、冻结、评测、回归和 reconcile 机制。

这些共用部分构成项目的稳定骨架，保证换领域后仍能得到可比较的质量证据。

## 哪些部分需要按领域定制

领域定制主要发生在科学内容层：

- 候选方法族及其适用条件；
- 输入数据的表示、单位、边界条件和来源说明；
- 真值或参考结果的独立计算方式；
- 误差、成本、守恒、稳定性或不确定度等评分指标；
- 领域特有的失败模式和合理提示；
- 运行资源、精度要求与预计完成时间。

例如，数值计算题需要关注收敛、残差和计算预算；图像题可能关注结构保持和噪声鲁棒性；统计题则需要关注抽样、区间估计和数据泄漏。领域定制不能改变“必须真实比较方法并迁移到未见工况”的根本要求。

## 从不同输入动态适配

面对研究课题时，系统先把研究问题拆成可比较的方法路线和可观测结果；面对知识图谱时，系统先确定实体、关系和可验证查询，再决定适合的方法选择或推理任务；面对论文与软件组合时，则把论文中的科学目标、软件中的可执行能力和数据中的可观测变量对齐。

每种新输入类型都可以建立自己的 profile 和 Experience Cards，但只有在多次任务中出现稳定、可迁移的规律后，才会上升为新的题型规范。这样既能快速适配新领域，也能避免把一次性的做法误当成通用规则。

## Skill Bank 的意义

Skill Bank 不是提示词仓库，而是出题流程的可验证记忆。它记录：

1. 当前稳定的通用执行规范；
2. 某种输入、题型或阶段的适用经验；
3. 失败案例的归因、修复假设和回归结果；
4. 每批题目实际使用的版本快照。

因此，题目越多，流程应当越稳定，而不是不断重复相同错误。每次新批次重新 resolve，使用经过评测的稳定版本；失败经验先沉淀、再验证、后升级。

## Q8 示例：Airfoil 鲁棒交叉验证路线选择

本次 Q8 采用翼型自噪声数据作为科学背景，围绕鲁棒交叉验证路线选择组织题目。题面向解题者提供公开任务说明和必要资源，隐藏侧保留用于评分的参考结果；题目要求解题者基于数据和科学目标选择合适的验证路线，而不是读取隐藏标签。

Q8 体现了 TaskFoundry 的几个关键设计：公开资源与私有评分数据分离，候选路线具有明确的科学差异，评分同时关注选择结果与数值质量，题包包含独立 verifier 和资源说明，解题 trace 则用于检查是否真正完成了科学推理。它也作为流程演练案例，帮助检验题纲、题型规范、题包结构和盲解记录能否贯通。

## 结果如何对外呈现

每道题的目录保存题纲、题包、资源说明和两层 trace：一层记录出题过程中的尝试与归因，另一层记录最终版本的盲解、提示和发布验证。最终对外发布的只包含经过确认的题目版本；失败候选和私有答案留在受控的内部记录中，不进入公开题包。

最终交付关注的是一条完整证据链：题目来源清楚、题面可理解、任务确实可解、方法选择具有科学意义、评分可复现、盲解结果稳定，并且所有关键版本都能追溯。
